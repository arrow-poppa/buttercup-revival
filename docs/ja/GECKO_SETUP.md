# Firefox、Zen、その他の Gecko ブラウザで Buttercup をセットアップする

Buttercup Revival は **Chromium と Gecko** 向けのブラウザ拡張機能です。このガイドでは、Windows と Linux での Gecko ビルドを扱い、Zen Flatpak をローカルアシスタントに接続する 2 つの方法を説明します。

2 つの部分をインストールします: 拡張機能は YouTube に BC ボタンを追加し、アシスタントはお使いのコンピューターで音声を準備します。未署名拡張機能のインストールとアシスタントの接続は別の手順です。署名設定を変更しても、Flatpak のネイティブメッセージング制限は解除されません。

## ルートを選ぶ

| お使いのブラウザ | 拡張機能のインストール | アシスタントの接続 |
| --- | --- | --- |
| ネイティブ Zen | 以下の永続的な未署名インストール、または一時インストール | **Start and connect** をクリック |
| 標準 Firefox リリース | 永続インストール用の Mozilla 署名済みパッケージ、または一時インストール | ネイティブインストールで **Start and connect** をクリック |
| Firefox ESR、Developer Edition、Nightly、またはブランドなしビルド | 対応ビルドでは未署名インストールが可能。署名表を参照 | ネイティブインストールで **Start and connect** をクリック |
| Zen Flatpak | Zen と同様にインストール | **方法 A: Flatseal による自動接続** または **方法 B: 手動接続** を選択 |
| その他のモダンな Gecko フォーク | 署名表とブラウザーの要件を確認 | ネイティブメッセージングはブラウザー/パッケージによって異なります。[互換性の詳細](../firefox.md)を参照 |

Buttercup は Gecko 140 以降を対象としています。署名サポートがあるだけでは、すべてのフォーク/パッケージが Buttercup でテスト済みであることにはなりません。Firefox ネイティブと Zen ネイティブ/Flatpak は実行時検証済みです。LibreWolf と Waterfox は個別の実行時テストを行っていません。

<a id="extract"></a>
## 1. 正しいパッケージを展開する

1. Buttercup プロジェクトの完全な ZIP を、ドキュメントなど保持する予定のフォルダーに展開します。
2. 展開したフォルダーを開きます。`install.sh`、`scripts`、`dist` が含まれている必要があります。最初のフォルダー内に別の `Buttercup-Revival` フォルダーがある場合があります。それらのファイルを含む方を開いてください。
3. `dist/firefox/manifest.json` と `dist/firefox-unsigned.zip` が存在することを確認します。古い Chromium 専用パッケージには含まれていません。**v0.6.0 以降**をダウンロードするか、[ソースからビルド](../../README.ja.md#developers)してください。

**プロジェクト全体の ZIP** にはアシスタントとインストーラーが含まれます。小さい方の **`dist/firefox-unsigned.zip`** には拡張機能のみが含まれます。アドオンをインストールするときは小さい ZIP を選択し、プロジェクト全体の ZIP は選択しないでください。

インストール後も、展開したプロジェクトフォルダーをその場所に置いておいてください。移動するとアシスタントのランチャーが壊れる可能性があります。

## 2. インストーラーを実行する

**Windows:** そのフォルダーの `Install Buttercup.cmd` をダブルクリックします。

**Linux:** **そのフォルダー内**でターミナルを開き、次を実行します:

```sh
sh install.sh
```

ファイルマネージャーに**ターミナルで開く**アクションがあれば使用してください。なければ、先に `cd` でフォルダーに移動します。たとえば、ダウンロードに直接展開した場合:

```sh
cd "$HOME/Downloads/Buttercup-Revival"
```

このパスはあくまで例です。実際のフォルダーを使用してください。スペースや `(1)` を含むパスは引用符で囲んでください。プロンプトが `:~$` で終わる場合、通常はまだホームフォルダーにいて、プロジェクト内ではありません。

インストーラーは `.venv` を作成し、両方のブラウザエンジンを自動的に登録します。再実行すると環境を再利用し、依存関係の更新を確認します。インストール完了の報告があるまで待ってください。

## 3. 拡張機能をインストールする

### Zen で未署名拡張機能をインストールしたままにする

Zen は、署名の強制が無効になっている場合、ブラウザーの再起動後も未署名拡張機能をインストールしたままにできます:

1. 新しいタブを開き、`about:config` と入力します。
2. 設定の警告を承認します。
3. `xpinstall.signatures.required` を検索します。
4. 値を **`false`** に設定します。
5. `about:addons` を開くか、**Ctrl+Shift+A** を押します。
6. 歯車メニューを開き、**ファイルからアドオンをインストール…** を選択します。
7. 展開したプロジェクトから **`dist/firefox-unsigned.zip`** を選択し、インストールを承認します。
8. 拡張機能メニューから Buttercup を開きます。必要ならアイコンをピン留めします。

Buttercup には、永続インストールに必要な明示的な Gecko アドオン ID がすでに含まれています。ZIP と展開済みの Firefox フォルダーは**同じ ID** を使用します。ZIP を `.xpi` に名前変更しても署名されません。

この設定はブラウザープロファイルの署名強制を無効にするため、信頼できる拡張機能のみを使用してください。Zen の[公式ビルド設定](https://github.com/zen-browser/desktop/blob/dev/configs/common/mozconfig)は未署名アドオンを許可しており、この方法は Zen でテスト済みです。標準の Firefox リリースビルドとは異なります。

<a id="other-browsers"></a>
### 他にどのブラウザで許可されますか?

| ブラウザ/ビルド | 設定で永続的な未署名拡張機能を許可できるか | 根拠 |
| --- | --- | --- |
| **Zen** | はい: `xpinstall.signatures.required` を `false` に設定 | 公式ビルド設定と Zen での実行時テスト |
| **標準 Firefox リリース** | **いいえ。** 設定を変更してもリリースビルドの署名要件は回避できません | Mozilla のドキュメント |
| **Firefox ESR** | はい (Mozilla によると、対応する ESR ビルド) | Mozilla のドキュメント。ここでは独立した実行時テストなし |
| **Firefox Developer Edition / Nightly** | はい (テスト用) | Mozilla のドキュメント。ここでは独立した実行時テストなし |
| **ブランドなし Firefox ビルド** | はい (署名強制を無効にしてビルドした場合) | Mozilla のドキュメント。ここでは独立した実行時テストなし |
| **LibreWolf** | 公式ビルド設定は未署名アドオンを許可。設定で強制を制御可能 | ソースで確認済み。ここでは独立した実行時テストなし |
| **モダン Waterfox** | 公式デスクトップビルド設定は未署名アドオンを許可。設定で強制を制御可能 | ソースで確認済み。ここでは独立した実行時テストなし |

実際のブラウザのエディションとパッケージを確認してください。フォーク名や設定の存在だけでは、バイナリがそれを尊重する証拠にはなりません。古いフォーク、サードパーティビルド、ディストリビューションのポリシーは異なる場合があります。この表は署名に関するものであり、Buttercup の互換性やネイティブホストのサポートを保証するものではありません。

出典: [Mozilla: アドオンの署名](https://support.mozilla.org/en-US/kb/add-on-signing-in-firefox)、[Zen のビルド設定](https://github.com/zen-browser/desktop/blob/dev/configs/common/mozconfig)、[LibreWolf のビルド設定](https://librewolf.dev/librewolf/source/src/branch/main/assets/mozconfig.new)、[Waterfox の共有デスクトップビルド設定](https://github.com/BrowserWorks/Waterfox/blob/current/waterfox/build/mozconfig.common)。2026-11-13 に確認。

### 一時インストール (標準 Firefox を含む)

署名設定を変更したくない場合、または使用中のビルドが署名を強制する場合:

1. `about:debugging#/runtime/this-firefox` を開きます。
2. **一時的なアドオンを読み込む…** をクリックします。
3. **`dist/firefox/manifest.json`** を選択します。

このインストールはブラウザーの終了時に削除されます。標準の Firefox リリースで永続インストールするには、Mozilla 署名済みパッケージを入手してください。メンテナーは、拡張機能を公開せずに Mozilla の[自己配布署名プロセス](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/)を使用できます。

<a id="connect"></a>
## 4. アシスタントを接続する

**ネイティブブラウザインストール:** Buttercup を開き、**Start and connect** をクリックします。バッジが **Connected** になるはずです。以下の Flatpak の方法はどちらも不要です。

**Zen Flatpak:** 次のいずれかの方法を選択します。どちらも同じアシスタントを使用し、プロバイダー設定を保持します。

<a id="flatseal"></a>
### 方法 A: Flatseal による自動接続

**Start and connect** でアシスタントを起動したい場合 (コンピューターの再起動後も含む) は、こちらを選択してください。

#### A1. ランチャーを一度準備する

ステップ 2 と同様に、**インストール済みの Buttercup プロジェクトフォルダー内**でターミナルを開きます。次を実行します:

```sh
.venv/bin/python scripts/setup-assistant.py --flatpak-bridge app.zen_browser.zen
```

**Flatpak launcher prepared** と表示されるまで待ちます。このコマンドはブリッジを作成しますが、Flatpak の権限は変更しません。再実行するとランチャーが更新されます。

#### A2. Flatseal に 2 つのエントリを追加する

**Flatseal** を開き、アプリケーション一覧で **Zen** (`app.zen_browser.zen`) を選択します (「すべてのアプリケーション」ではありません)。

| このセクションを見つける | この値を正確に追加する |
| --- | --- |
| **Session Bus → Talks** | `org.freedesktop.Flatpak` |
| **Persistent → Files** | `.mozilla` |

各エントリについて、セクションの **+** またはエントリ追加ボタンを使用し、値を入力して確定します。`.zen` などの既存のエントリは残してください。

**これらはテキストエントリであり、Socket セクションの D-Bus スイッチではありません。** セッションバス全体、システムバス全体、すべてのユーザーファイル、すべてのファイルシステムを有効にする必要はありません。最初の値は大文字と小文字を区別します。2 番目はドットで始まり、スラッシュは含みません。

セッションバスの権限により、Zen は Buttercup だけでなく、ホストプログラム全般を実行できます。この権限を無効のままにしたい場合は方法 B を使用してください。テスト済みの方法では Zen の既定のファイルシステム権限を使用します。カスタムのホームディレクトリ上書きが広いと、永続マッピングに干渉する可能性があります。[Flatseal の権限リファレンス](https://github.com/tchx84/Flatseal/blob/master/DOCUMENTATION.md)を参照してください。

#### A3. 再起動して接続する

1. 他のウィンドウやバックグラウンドインスタンスを含め、Zen を完全に終了します。
2. Zen を再度開きます。
3. Buttercup を開き、**Start and connect** をクリックします。
4. バッジが **Connected** と表示されることを確認します。

以後は通常どおり **Start and connect** を使用します。コンピューターの再起動後もアシスタントを起動できます。接続ファイルやターミナルは不要です。

<a id="manual"></a>
### 方法 B: 追加の Flatpak 権限なしで手動接続

Zen の既定のサンドボックス権限を維持したい場合は、こちらを選択してください。接続ファイルを一度作成し、コンピューターの再起動後にヘルパーでアシスタントを起動します。

#### B1. ブラウザーの接続オリジンをコピーする

1. 使用するブラウザープロファイルで Buttercup を開きます。
2. **Connect without native messaging** を展開します。
3. **Copy origin** をクリックします。

そのボタンの値を使用してください。How to connect の **Extension ID** はコピーしないでください。接続オリジンは `moz-extension://` で始まり、このブラウザープロファイルを識別します。

#### B2. プライベート接続ファイルを作成する

1. 展開したプロジェクトフォルダーで **Set up Buttercup assistant.sh** を実行します。ファイルマネージャーがスクリプトをテキストとして開く場合は、そのフォルダーで開いたターミナルで `sh "Set up Buttercup assistant.sh"` を実行します。
2. セットアップウィンドウで **Flatpak / Snap: connect manually** を見つけます。
3. そのフィールドにオリジンを貼り付けます。
4. **Start assistant and save connection file** をクリックします。
5. JSON ファイルを、ダウンロードなど見つけやすい場所に保存します。

ヘルパーはアシスタントをバックグラウンドで起動します。ターミナルを開いたままにする必要はありません。

#### B3. 接続をインポートして確認する

1. Buttercup → **Connect without native messaging** に戻ります。
2. **Open connection editor** をクリックします。ポップアップが閉じてもファイルピッカーを開いたままにできるよう、タブが開きます。
3. 先ほど保存した JSON ファイルを選択します。
4. **Import connection** をクリックします。
5. **Assistant connected** / **Connected** と表示されることを確認します。
6. 後で JSON ファイルを削除します。これにはプライベートなローカルアシスタントトークンが含まれています。

インポートした接続はそのプロファイルに保存されたままになります。プロバイダーや字幕の設定を変更しても削除されません。新しいブラウザープロファイルには新しいファイルが必要です。設定バックアップにはローカル接続が意図的に含まれません。

#### B4. コンピューターの再起動後

同じプロジェクトフォルダーから **Start Buttercup assistant.sh** を実行します。必要なら、そこでターミナルを開いて次を実行します:

```sh
sh "Start Buttercup assistant.sh"
```

次に、Buttercup で **Check connection** をクリックします。再起動のたびに JSON ファイルを作成/インポートし直す必要はありません。この方法では、**Start and connect** は引き続きネイティブメッセージングを試みます。代わりにヘルパーと **Check connection** を使用してください。

## 5. 最初の字幕を生成する

1. **Transcription** でプロバイダーを選択し、API キーを入力します。
2. YouTube 動画を開きます。
3. プレーヤーの **BC** ボタン、または Buttercup の **Generate captions** をクリックします。
4. 完了メッセージを待ちます。

**Generate** は利用可能な場合はキャッシュされた文字起こしを再利用します。**Regenerate subtitles** は明示的に新しい文字起こしを要求し、プロバイダー料金が発生する場合があります。**Start a new subtitle** で、プロバイダーの元のセグメントを選択するか、Buttercup に再グループ化させます。レイアウトの変更は既存のキャッシュを使用できます。

## 問題が発生した場合

| 表示される内容 | 対処方法 |
| --- | --- |
| `.venv/bin/python: No such file or directory` | 間違ったフォルダーにいるか、インストーラーが完了していません。`install.sh` と `scripts` を含むフォルダーを開き、そこでターミナルを開き、`.venv` がない場合は `sh install.sh` を実行してください。`~` から相対コマンドを実行しないでください。 |
| `unrecognized arguments: --flatpak-bridge` | 古いパッケージ、または別の展開コピーのスクリプトを実行しています。更新されたデュアルブラウザーパッケージとそのプロジェクトフォルダーを使用してください。 |
| 未署名拡張機能が拒否される | プロジェクトアーカイブ全体ではなく、`dist/firefox-unsigned.zip` を選択してください。ブラウザー/ビルドの表と署名設定を確認してください。標準 Firefox リリースには署名済みパッケージまたは一時読み込みが必要です。 |
| ブラウザーの再起動後に拡張機能が消える | 一時的に読み込まれました。そのブラウザーが対応する永続インストール、または署名済みパッケージを使用してください。 |
| 拡張機能はインストールされているがアシスタントが接続できない | これは署名とは別の問題です。ネイティブユーザーはインストーラーを再実行してください。Flatpak ユーザーは方法 A または B を完了してください。 |
| 方法 A でも接続できない | ランチャーコマンドが成功したこと、両方の Flatseal エントリが Zen 自体に追加されたこと、Zen が完全に再起動されたことを確認してください。プロジェクトフォルダーをその場所に置いておいてください。カスタムのファイルシステム上書きがある場合は、手動の方法に戻す必要があるかもしれません。 |
| 方法 B でファイルが別のプロファイルのものだと表示される | 現在のプロファイルからオリジンをコピーし、新しい接続ファイルを生成してください。 |
| コンピューターの再起動前は方法 B が機能していた | `Start Buttercup assistant.sh` を実行し、**Check connection** をクリックしてください。通常、再インポートは不要です。 |

テスト済みのバージョン、制限事項、手動 CLI オプション、セキュリティ設計については、[Gecko の技術および互換性ノート](../firefox.md)を参照してください。
